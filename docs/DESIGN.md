# 카카오톡 간편 모드 설계 문서

갱신일: 2026-10-15

간편 모드의 중심 과업은 **사용자가 하고 싶은 일을 일상적인 말로 설명하면 필요한 기능을 찾아 이동하는 것**입니다. 이 문서는 그 의도와 2026년 웹 구현 범위, 화면 연결 및 후속 검증 항목을 설명합니다.

## 문제와 설계 방향

메신저에 필요한 기능이 있어도 사용자는 정확한 이름이나 메뉴 위치를 모를 수 있습니다. 모든 기능을 홈에 늘어놓으면 화면이 복잡해지고, 메뉴를 줄이면 다른 기능을 찾기 어려워질 수 있습니다.

간편 모드는 홈에 친구·대화·기능 찾기·도움말만 크게 배치하고, 그 밖의 기능은 기본 화면에서 숨겨 정보량을 줄입니다. 사용자는 기능 찾기에 “생일 선물 보내고 싶어”처럼 자신의 목표를 적고, 결과의 기능 이름과 설명을 확인한 뒤 해당 화면으로 이동합니다. 모호한 요청에는 후보를 확인하고, 검색 결과가 없을 때는 다시 입력하거나 지원 기능 목록으로 탐색을 이어갑니다. 홈의 단순함과 다른 기능에 대한 접근을 함께 고려한 설계입니다.

## 2020년 기획과 2026년 구현

| 구분               | 근거와 범위                                                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| 2020년 팀 아이디어 | 고령층 페르소나와 이용 특성을 고려해 핵심 메뉴만 기본 화면에 남기고, 다른 기능은 일상 문장으로 찾는 간편 모드와 검색 예외 대응 흐름 기획 |
| 2026년 Figma 제작  | 핵심 화면·컴포넌트, 기능 검색·후보 확인·검색 결과 없음·기능 화면 이동을 연결한 사용자 흐름 프로토타입 |
| 2026년 웹 구현     | 기능 목록과 표현 규칙, 검색 결과·기능별 체험 화면·로컬 설정을 연결하는 실제 브라우저 동작           |

2020년 팀 프로젝트에서 제안한 간편 모드를 2026년 Figma 프로토타입과 웹 데모로 구체화했습니다. 웹의 표현 매칭 규칙과 기능별 체험 동작은 2026년 후속 구현에 해당합니다.

원본에는 팀의 조사 활동에 관한 기록이 있지만 이번 웹 데모의 사용자 테스트나 효과 측정 자료로 사용하지 않습니다.

## 핵심 사용자 흐름

1. 홈에서 기능 찾기를 선택합니다.
2. 하고 싶은 일을 문장으로 입력하거나 예시 문장을 고릅니다.
3. 결과에서 기능 이름과 할 수 있는 일을 확인합니다.
4. 원하는 결과를 선택해 기능 화면으로 이동합니다.
5. 가상 데이터로 기능을 체험하고 이전 화면이나 홈으로 돌아옵니다.

결과를 제시하는 데서 끝내지 않고 해당 기능의 화면까지 연결합니다. 과업과 연결되지 않는 입력에는 표현을 바꾸거나 예시를 활용해 다시 찾을 수 있는 다음 행동을 안내하는 것을 설계 기준으로 삼습니다.

## 화면의 역할

| 화면             | 목적과 연결                                                                    |
| ---------------- | ------------------------------------------------------------------------------ |
| 간편 모드 홈     | 친구·대화·기능 찾기·도움말의 네 가지 큰 메뉴를 제공                            |
| 기능 찾기        | 사용자의 과업 문장을 받고 결과의 이름·설명·이동 행동을 표시                    |
| 기능별 체험 화면 | 선택한 기능의 목적을 확인하고 샘플 동작이나 로컬 설정을 체험                   |
| 친구·대화 목록   | 가상의 상대를 선택하거나 이전 대화와 초안을 이어 보기                          |
| 채팅방           | 텍스트나 샘플 콘텐츠를 가상 대화에 표시                                        |
| 도움말           | 기능 찾기 사용법과 과업별 안내 제공                                            |
| 모드 설정        | 변경 내용을 설명하고 취소·확정, 기본 모드의 비교용 화면 및 간편 모드 복귀 제공 |

기본 모드는 여러 메뉴가 모여 있는 비교용 예시 화면입니다. 실제 카카오톡 기본 모드를 재현하거나 화면 속 메뉴의 기능을 각각 구현한 것은 아닙니다.

## 기능 목록과 목적지

| 기능 ID        | 기능        | 표현 예시               | 웹 데모에서의 동작                                                   |
| -------------- | ----------- | ----------------------- | -------------------------------------------------------------------- |
| `photo`        | 사진 보내기 | 사진 보내고 싶어        | 샘플 사진을 선택해 가상 대화에 표시                                  |
| `video-call`   | 영상통화    | 얼굴 보고 통화하고 싶어 | 영상통화 화면 시연. 카메라·마이크 사용 없음                          |
| `voice-call`   | 음성통화    | 전화하고 싶어           | 음성통화 화면 시연. 마이크 사용 없음                                 |
| `gift`         | 선물하기    | 생일 선물 보내고 싶어   | 샘플 선물을 선택해 가상 대화에 표시. 실제 주문·결제 없음             |
| `font`         | 글자 크기   | 글씨를 크게 보고 싶어   | 기본·더 크게 중 선택하고 데모의 안내 글과 대화 내용에 적용           |
| `profile`      | 프로필      | 내 이름을 바꾸고 싶어   | 웃는 얼굴·꽃·산의 시연용 그림, 이름 20자, 소개 문구 80자를 로컬 저장 |
| `notification` | 알림 설정   | 알림을 끄고 싶어        | 데모 알림 설정. 기기의 실제 알림 권한 변경 없음                      |
| `emoticon`     | 이모티콘    | 이모티콘 보내고 싶어    | 샘플 이모티콘을 가상 대화에 표시                                     |
| `voice-input`  | 음성 입력   | 말로 메시지를 쓰고 싶어 | 준비된 예시 문구 입력. 마이크·음성 인식 사용 없음                    |

목적지는 실제 서비스의 기능 화면을 설명하기 위한 로컬 체험입니다. 카카오톡 계정이나 실서비스 기능을 호출하지 않습니다.

## 기능 찾기의 구현 기준

- 브라우저에 정의된 기능 목록과 표현 규칙으로 입력을 대응시킵니다.
- 입력은 Unicode 코드 포인트 기준 200자까지이며, 빈 입력에서는 찾기 동작을 진행하지 않습니다.
- 검색 입력을 처리하기 위해 외부 네트워크, 백엔드 또는 LLM API를 사용하지 않습니다.
- 결과에 기능 이름과 설명을 함께 표시해 사용자가 자신의 의도와 맞는지 확인할 수 있게 합니다.
- “사진”이나 “통화”처럼 여러 기능에 해당하는 표현, 여러 과업 또는 부정 표현이 섞인 문장에는 후보를 확인하도록 안내합니다. 문장의 의미를 완전히 해석하는 기능은 아닙니다.
- 결과를 선택하면 해당 기능의 체험 화면으로 이동합니다.
- 일치하는 결과가 없을 때는 다시 적기와 지원 기능 목록을 통해 탐색을 이어갈 수 있도록 합니다.

이 규칙은 2026년 데모를 위해 만든 제한된 구현입니다. 모든 한국어 표현을 이해하거나 실제 카카오톡의 검색 알고리즘을 재현한다고 주장하지 않습니다. 사용자 표현의 범위를 확인하면서 기능별 표현과 안내를 보완해야 합니다.

## 대화와 로컬 상태

| 조건 또는 행동      | 동작 기준                                                                 |
| ------------------- | ------------------------------------------------------------------------- |
| 메시지 입력         | 최대 500자. 내용이 없으면 전송하지 않음                                   |
| 전송                | 가상 대화에 즉시 추가하고 ‘보냈어요’ 표시                                 |
| 작성 중 화면 이동   | 상대별 초안 보존                                                          |
| 재방문              | 저장된 가상 대화·초안·데모 설정을 같은 브라우저에서 복원                  |
| 메시지 보관         | 전체 대화에서 최근 300개까지 유지                                         |
| 저장 차단·공간 부족 | 현재 탭에서 체험을 계속하고 최근 변경 사항이 저장되지 않을 수 있음을 안내 |
| 체험 초기화         | 별도 버튼에서 확인한 뒤 대화·초안·설정을 초기 상태로 되돌림               |

저장은 현재 브라우저의 `localStorage` 범위입니다. 다른 기기와 동기화하지 않습니다. 사이트 데이터를 지우면 저장 상태도 사라지며, 저장하지 못한 최근 변경 사항은 재방문 때 복원되지 않을 수 있습니다.

저장 형식 갱신 시 이전 버전의 미전송 문구는 초안으로 보존합니다.

## Figma 프로토타입과 웹 데모의 역할

Figma에서는 핵심 화면과 반복 UI 컴포넌트를 정리하고, 기능 찾기에서 결과 확인과 기능별 화면 이동까지 이어지는 사용자 흐름을 프로토타이핑했습니다. 모호한 요청의 후보 선택과 검색 결과 없음 상태의 재입력·기능 목록 안내도 준비된 화면과 상태 전환으로 연결합니다.

웹에서는 사용자가 직접 입력한 문장을 한국어 표현 규칙으로 처리하고, 결과에 따른 화면 이동과 가상 데이터·로컬 설정의 변경을 구현합니다. Figma의 화면 연결과 웹의 입력 처리·브라우저 저장은 서로 다른 구현 범위입니다. 두 산출물은 핵심 메뉴, 기능 검색, 결과 확인, 체험 화면 이동과 검색 예외 대응이라는 공통 흐름을 설명합니다.

## 화면과 상호작용 기준

- 홈은 네 가지 핵심 메뉴를 큰 조작 영역과 짧은 설명으로 구성합니다.
- 기능 찾기는 정확한 메뉴 이름을 외우지 않아도 자신의 목표로 시작할 수 있게 합니다.
- 결과 이름과 설명을 읽고 원하는 기능을 선택하도록 합니다.
- 기능 화면에서는 지금 체험하는 기능과 돌아갈 경로를 명확히 표시합니다.
- 긴 문장과 큰 글자에서도 내용을 읽을 수 있도록 줄바꿈과 요소 높이를 검토합니다.
- 선택과 적용·전송 완료 상태는 색상에만 의존하지 않고 글자로도 알립니다.
- 키보드로 입력·결과 선택·화면 이동을 수행할 수 있는지 확인합니다.

이는 설계와 검토 기준이며 접근성 표준 인증을 의미하지 않습니다.

## 구현 검증 항목

개편된 버전의 실행 결과는 [검증 기록](VALIDATION.md)에 따로 기재합니다.

- 사진·영상통화·선물 예시가 해당 기능을 찾는지
- 음성통화·글자 크기·프로필·알림·이모티콘·음성 입력의 표현과 목적지가 대응하는지
- 결과에서 실제 체험 화면으로 이동하고 돌아올 수 있는지
- 정의되지 않은 표현에도 탐색을 이어갈 안내가 있는지
- 샘플 콘텐츠가 가상 대화에 표시되고 설정이 로컬 범위에서 적용되는지
- 자유 입력·초안·저장·모드 변경이 기능 탐색과 함께 동작하는지
- 좁은 화면의 가독성, 키보드 초점, 안전한 문자열 표시가 유지되는지

```sh
node --test tests/*.test.mjs
```

## 미검증 가설과 후속 사용자 테스트

| 설계 가설                                                | 관찰할 질문                                                       |
| -------------------------------------------------------- | ----------------------------------------------------------------- |
| 네 가지 메뉴가 시작점을 고르기 쉽게 한다                 | 사용자가 도움 없이 기능 찾기를 발견하는가?                        |
| 과업 문장으로 시작하면 기능 이름을 몰라도 접근할 수 있다 | 사용자는 어떤 표현을 입력하며 정의된 규칙이 그 표현을 포괄하는가? |
| 결과의 이름과 설명이 의도 확인에 도움이 된다             | 결과를 읽고 자신이 원하는 기능인지 판단하는가?                    |
| 검색 결과에서 바로 이동하면 탐색을 이어가기 쉽다         | 해당 기능 화면에 도착한 뒤 다음 행동을 이해하는가?                |
| 홈의 정보량을 줄여도 필요한 기능에 접근할 수 있다        | 홈에 없는 기능을 찾을 때 막히는 지점은 어디인가?                  |

실제 참가자를 대상으로 한 테스트와 개선 효과 측정은 아직 진행하지 않았습니다. 구현 동작 검사를 과업 시간 단축이나 사용성 개선을 입증하는 실험으로 해석하지 않습니다.

## 공개 범위

공개 자료는 웹 코드, 가상 데이터, 선별한 시각 자료와 문서입니다. 원본 수업 PPT·PDF·영상과 내부 작업 기록은 포함하지 않습니다. Figma 원본은 팀 접근 권한으로 관리하므로 외부 접근을 보장하지 않습니다.
