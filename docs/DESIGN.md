# 카카오톡 간편 모드 설계 문서

이 문서는 2026년 후속 리디자인과 인터랙티브 웹 데모의 화면 목적, 상태 전환 및 검증 범위를 설명합니다. 카카오 공식 디자인 시스템이나 실제 서비스 사양을 나타내지 않습니다.

## 문제와 설계 가설

메신저 기능이 많아질수록 메뉴를 이해하거나 필요한 조작을 찾기 어려운 사용자가 있을 수 있습니다. 이 프로젝트는 연령 자체보다 작은 글자, 익숙하지 않은 아이콘, 사용법을 기억하기 어려운 상황과 잘못 누른 뒤의 복구에 주목합니다.

핵심 가설은 기능을 선택적으로 단순화하고 주요 행동을 큰 요소와 익숙한 말로 표현하면 대화를 시작하기 쉬워질 수 있다는 것입니다. 고령층 전체의 특성이나 검증된 사용성 결과로 일반화하지 않습니다.

## 원본과 후속 제작의 구분

| 구분 | 근거와 범위 |
|---|---|
| 2020년 팀 아이디어 | 고령층 페르소나의 소통 목표, 기능 과다와 사용법 기억의 어려움, 필요한 기능의 큰 표시, 도움말, 간편 모드라는 접근 방향 |
| 2026년 Figma 제작 | 핵심 화면, 공통 요소, 정상·예외 상태, 연결된 프로토타입과 설계 기준의 첫 구체화 |
| 2026년 웹 구현 | 브라우저 입력, 전송 상태 시뮬레이션, 동일 메시지 재시도, 초안·가상 대화의 로컬 저장 |

한재혁이 참여한 2020년 팀의 아이디어 제안을 바탕으로, 2026년에 처음으로 Figma 프로토타입과 웹 데모를 제작했습니다.

원본의 조사 활동 기록과 현재 검증 가능한 자료는 구분합니다. 당시 인터뷰의 질문지·표본·원자료를 이번 공개 저장소에 포함하지 않으며, 그 기록을 데모의 사용성 개선 효과를 입증하는 근거로 사용하지 않습니다.

## 화면 목적

| 화면 | 사용자의 목표 | 주요 연결 |
|---|---|---|
| 간편 모드 홈 | 필요한 일을 고르기 | 친구, 대화, 친구 찾기, 도움말, 모드 설정 |
| 친구 목록 | 대화할 사람 선택하기 | 친구 검색, 선택한 상대의 채팅방 |
| 대화 목록 | 이전 대화 이어 보기 | 채팅방, 작성 중인 초안, 빈 목록에서 친구 선택 |
| 채팅방 | 메시지 작성과 전송 상태 확인 | 입력, 전송, 재시도, 목록 복귀 |
| 모드 설정 | 변경 내용을 이해하고 선택하기 | 변경 확인, 취소, 일반 모드 완료 안내, 간편 모드 복귀 |

검색 결과 없음, 도움말 답변, 전송 중·실패·완료, 모드 확인은 위 과업을 보완하는 상태입니다. 일반 모드 전체 화면을 별도로 재현하지 않습니다.

## 메시지와 저장 상태

| 조건 또는 행동 | 동작 기준 |
|---|---|
| 입력 | 최대 500자까지 입력할 수 있습니다. 내용이 없으면 메시지를 전송하지 않습니다. |
| 전송 시작 | 메시지에 식별자를 부여하고 전송 진행 상태를 표시합니다. 약 900ms 뒤 시뮬레이션 결과를 보여 줍니다. |
| 전송 진행 중 | 진행 여부를 글자로 알리고 중복 전송을 막습니다. 실제 네트워크 응답 시간의 측정값이 아닙니다. |
| 전송 완료 | 보낸 메시지와 완료 상태를 표시하고 대화 목록에 해당 상태를 반영합니다. |
| 전송 실패 | 해당 메시지의 내용을 보존하고 실패 상태와 다시 보내기 행동을 제공합니다. |
| 다시 보내기 | 실패한 메시지의 같은 식별자를 사용해 진행·완료 상태로 바꿉니다. 새 메시지를 중복 생성하지 않습니다. |
| 작성 중 이동 | 대화 상대별 초안을 보존해 같은 대화로 돌아왔을 때 이어 쓸 수 있도록 합니다. |
| 다음 방문 | `localStorage`에 보존한 가상 대화와 초안을 같은 브라우저에서 복원합니다. |
| 메시지 보관 | 전체 대화에서 최근 메시지 300개까지 유지합니다. 한도를 넘으면 오래된 메시지부터 제외합니다. |
| 전송 중 새로고침 | 저장된 진행 상태를 실패 상태로 복원합니다. 같은 메시지 식별자로 다시 보내기를 할 수 있습니다. |
| 저장 차단 또는 공간 부족 | 현재 탭의 메모리에서 시연을 계속하며 최근 변경 사항이 저장되지 않을 수 있다고 안내합니다. 새로고침하면 마지막으로 저장된 상태가 남아 있을 수 있습니다. |

저장은 현재 브라우저 범위에 한정됩니다. 실제 계정, 서버 데이터베이스, 기기 간 동기화나 다른 사람에게 전달하는 메시지는 없습니다. 사이트 데이터를 삭제하면 저장된 시연 상태도 사라집니다. 저장에 실패하면 이전에 저장한 상태와 현재 탭의 최신 상태가 달라질 수 있으므로 최근 변경 사항의 재방문 복원을 보장하지 않습니다.

Figma는 준비된 프레임의 상태 전환을 보여 주므로 탐색 경로에 따라 초기 화면으로 돌아갈 수 있습니다. 웹 구현은 로컬 저장으로 초안과 대화 상태를 유지하며, 두 산출물의 동작 범위를 동일하다고 간주하지 않습니다.

## 검색·도움말·모드 전환

| 상황 | 사용자에게 보여 주는 기준 |
|---|---|
| 친구 검색 결과 없음 | 결과가 없다는 문구와 검색어를 바꾸거나 친구 목록으로 돌아갈 경로를 제공합니다. |
| 대화 목록 비어 있음 | 아직 대화가 없음을 알리고 친구 목록에서 대화를 시작하도록 안내합니다. |
| 사용법을 모름 | 과업을 질문형 제목으로 제시하고 답변에서 실제로 할 행동을 설명합니다. 답변에서 도움말 목록으로 돌아갈 수 있습니다. |
| 모드 변경 선택 | 변경 내용을 먼저 안내하고 취소와 확정 행동을 분리합니다. |
| 모드 변경 취소 | 기존 모드를 유지합니다. |
| 일반 모드 변경 확정 | 변경 완료 안내를 보여 줍니다. 실제 일반 모드의 전체 기능은 이번 범위에 포함하지 않으며 간편 모드로 돌아갈 수 있습니다. |

## 화면과 공통 요소의 기준

- 핵심 행동은 큰 조작 요소와 명확한 글자 라벨로 표시합니다.
- 같은 목적의 목록, 버튼, 입력창, 상태 메시지는 일관된 모양과 표현을 사용합니다.
- 실패·진행·선택을 색상만으로 전달하지 않고 글자와 형태를 함께 사용합니다.
- 긴 이름이나 설명이 잘리지 않도록 줄바꿈과 요소 높이를 함께 검토합니다.
- 가상 이름과 중립적인 아바타를 사용하며 원본 수업 자료의 인물 사진과 팀원 개인정보를 새 데모에 옮기지 않습니다.
- 작은 화면과 키보드 조작에서도 핵심 과업을 수행할 수 있는지 구현 검토 항목으로 삼습니다.

이 항목은 설계·검토 기준입니다. 특정 접근성 표준을 완전히 준수하거나 인증받았다는 의미는 아닙니다. 선택한 색상 조합의 대비 계산만으로 전체 접근성을 판단하지 않습니다.

## 확인할 동작

자동 테스트와 브라우저 검토에서는 다음과 같은 상태 변화를 확인합니다. 실제 통과 결과는 실행 결과를 기준으로 판단합니다.

1. 입력 제한과 빈 메시지 전송 방지
2. 전송 진행 중 중복 생성 방지
3. 실패한 메시지의 식별자를 유지하는 재시도
4. 화면 이동과 재방문 뒤 초안·대화 복원
5. 검색 결과 없음에서 목록으로 복귀
6. 빈 대화 목록에서 새 대화 시작
7. 도움말 답변과 이전 화면 사이의 이동
8. 모드 변경 취소·확정과 간편 모드 복귀
9. 전송 중 새로고침한 메시지의 실패 복원과 재시도
10. 저장 차단·공간 부족 시 안내와 현재 탭에서의 동작

자동 테스트 실행 명령:

```sh
node --test tests/*.test.mjs
```

자동 테스트와 제작자의 화면 검토는 실제 사용자가 얼마나 쉽게 이용하는지 입증하지 않습니다. Figma와 웹의 각 연결을 전수 검증했거나 개선 수치를 측정했다고 주장하지 않습니다.

## 미검증 가설과 후속 사용자 테스트

| 확인할 가설 | 후속 테스트에서 살펴볼 질문 |
|---|---|
| 큰 핵심 메뉴가 기능 찾기에 도움이 된다 | 도움 없이 대화할 친구를 선택할 수 있는가? 홈의 용어를 같은 의미로 이해하는가? |
| 질문형 도움말이 막힌 과업을 해결한다 | 맞는 질문을 찾고 답변을 읽은 뒤 실제 과업으로 돌아갈 수 있는가? |
| 전송 상태가 명확하다 | 보내는 중·실패·완료를 구분하고 실패한 메시지를 다시 보낼 수 있는가? |
| 초안 보존을 이해한다 | 목록으로 나간 뒤 작성 중인 대화를 다시 찾아 입력을 이어갈 수 있는가? |
| 모드 변경 안내가 선택을 돕는다 | 바뀌는 범위를 이해하고 원치 않는 변경을 취소할 수 있는가? |

후속 검증에서는 디지털 숙련도와 이용 조건이 다른 참가자의 과업 수행, 망설임, 오조작과 복구 과정을 관찰할 수 있습니다. 아직 참가자를 모집하거나 테스트를 실시하지 않았으므로 목표값·성과 수치·실사용자 인용을 제시하지 않습니다.

## 공개 자료와 AI 지원

공개 범위는 웹 코드, 가상 데이터, 검토한 시각 자료와 이 문서입니다. 원본 PPT·PDF·영상과 내부 작업 기록은 저장소에 포함하지 않습니다. Figma 원본의 현재 팀 권한은 외부 공개를 보장하지 않으므로 별도 접근 권한이 필요한 파일로 취급합니다.

2026년 제작에는 Codex를 통한 자료 정리, Figma 구성, 웹 코드와 문서 작성, 검토 지원을 활용했습니다. 한재혁은 프로젝트의 역사와 방향, 후속 구현 범위를 제공했습니다. 이 문서는 실제 산출물과 확인한 동작 범위를 기준으로 작성했습니다.
