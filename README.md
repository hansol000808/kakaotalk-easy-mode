# 카카오톡 간편 모드

큰 메뉴와 명확한 글자 안내로 친구 찾기, 대화 시작, 메시지 작성과 실패 복구를 체험하는 정적 웹 데모입니다. HTML, CSS, JavaScript로 동작하며 별도의 서버 데이터베이스나 로그인은 사용하지 않습니다.

**[웹 데모 열기](https://hansol000808.github.io/kakaotalk-easy-mode/)**

카카오의 공식 서비스가 아닌 컨셉 데모입니다. 모든 인물과 대화는 가상 데이터이며, 실제 카카오톡 계정이나 메시지 서비스에 연결하지 않습니다.

## 주요 기능

| 기능 | 동작 |
|---|---|
| 친구 선택 및 검색 | 가상 친구 목록에서 상대를 선택하거나 이름으로 검색합니다. 결과가 없으면 검색어 변경과 전체 목록 복귀를 안내합니다. |
| 대화 목록 | 이전 대화와 작성 중인 초안을 보여 줍니다. 빈 목록에서는 친구를 선택해 대화를 시작할 수 있습니다. |
| 메시지 입력 | 최대 500자까지 입력할 수 있으며, 빈 메시지와 전송 중 중복 전송을 막습니다. 길이는 Unicode 코드 포인트 기준입니다. |
| 전송 상태 | 보내는 중, 전송 완료, 전송 실패를 글자로 구분합니다. 약 900ms 뒤 결과를 보여 주는 시뮬레이션입니다. |
| 실패 복구 | 실패한 메시지의 식별자와 내용을 유지한 채 다시 보냅니다. 재시도로 메시지가 중복 생성되지 않습니다. |
| 초안 및 대화 저장 | 상대별 초안과 가상 대화를 현재 브라우저에 저장하고 다음 방문에 복원합니다. |
| 질문형 도움말 | 메시지 보내기, 전송 실패, 초안 찾기, 모드 변경을 단계별로 안내합니다. |
| 모드 변경 | 확인창에서 취소하거나 변경할 수 있습니다. 일반 모드는 변경 완료 안내까지만 보여 주며, 간편 모드로 돌아올 수 있습니다. |

## 사용 방법

1. 홈에서 **친구** 또는 **대화**를 선택합니다.
2. 대화할 친구를 누르고 메시지를 입력한 뒤 **보내기**를 선택합니다.
3. 작성 중 목록으로 이동했다가 돌아오면 초안을 이어 쓸 수 있습니다.
4. 화면 밖의 상황 선택 버튼으로 **전송 실패** 또는 **대화가 없을 때**를 확인합니다. 전송 실패 화면에서는 **다시 보내기**를 선택합니다.
5. **화면 모드 설정**에서 변경 내용을 확인하고, 취소 또는 일반 모드 변경을 선택합니다.

**처음부터**, **전송 실패**, **대화가 없을 때** 중 하나를 선택하고 확인창에서 다시 시작하면 현재 브라우저의 메시지와 초안이 선택한 예시로 초기화됩니다.

## 저장 및 복구

- 상태는 현재 브라우저의 `localStorage`에 저장합니다. 다른 기기나 브라우저와 동기화되지 않으며 사이트 데이터를 삭제하면 저장 상태도 사라집니다.
- 전체 대화에서 최근 메시지 300개까지 유지합니다. 한도를 넘으면 오래된 메시지부터 제외합니다.
- 전송 중 새로고침하면 진행 중이던 메시지를 실패 상태로 복원합니다. 같은 메시지를 다시 보낼 수 있습니다.
- 저장이 차단되거나 공간이 부족하면 안내를 표시하고 현재 탭의 메모리에서 동작을 이어갑니다. 최근 변경은 저장되지 않을 수 있으며, 새로고침하면 마지막으로 저장된 상태만 남거나 새로 시작할 수 있습니다.
- 입력한 내용을 메시지 서버에 전송하지 않습니다. 가상 문구로 기능을 체험할 수 있습니다.

## 로컬 실행

Node.js 20 이상이 필요합니다. 별도의 패키지 설치나 빌드 과정은 없습니다.

```sh
git clone https://github.com/hansol000808/kakaotalk-easy-mode.git
cd kakaotalk-easy-mode
node scripts/serve.mjs
```

[http://127.0.0.1:4173](http://127.0.0.1:4173)에 접속합니다. 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.

웹 화면은 정적 파일로 구성되어 GitHub Pages에서 제공할 수 있습니다. `scripts/serve.mjs`는 로컬 확인용 서버입니다.

## 검사 실행

```sh
node --test tests/*.test.mjs
node scripts/check.mjs
node --check app.js
```

- 상태 테스트는 빈 입력, 중복 전송, 동일 메시지 재시도, 모드 변경과 저장 복원, 중단된 전송, 한글 검색, Unicode 길이 제한, 손상된 저장 데이터 등을 다룹니다.
- 공개 파일 검사는 로컬 에셋 존재, 제외 대상 파일 및 자격 증명 패턴을 확인합니다.
- 확인한 환경과 결과는 [검증 기록](docs/VALIDATION.md)에 정리되어 있습니다.

## 기술 구성과 파일 구조

| 경로 | 역할 |
|---|---|
| `index.html` | 페이지 구조, 시연 화면 영역, 상황 선택과 확인창 |
| `styles.css` | 화면 스타일과 반응형 배치 |
| `app.js` | 화면 렌더링, 탐색, 입력 이벤트, 전송 타이머와 브라우저 저장 |
| `state.js` | 가상 데이터, 입력 제한, 전송 및 재시도, 초안, 저장 데이터 정규화 |
| `assets/icons/` | Lucide 기반 SVG 아이콘 |
| `tests/state.test.mjs` | Node.js 기본 테스트 러너를 사용하는 상태 테스트 |
| `scripts/serve.mjs` | 로컬 정적 파일 서버 |
| `scripts/check.mjs` | 에셋과 공개 파일 범위 검사 |
| `docs/DESIGN.md` | 화면 목적, 상태 전환 및 복구 동작 기준 |
| `docs/VALIDATION.md` | 검사 결과와 확인 범위 |

브라우저에서는 ES 모듈과 `localStorage`를 사용합니다. 전송은 실제 네트워크 요청 없이 타이머와 상태 전환으로 처리합니다. 아이콘 출처는 [에셋 문서](assets/README.md), 라이선스는 [LUCIDE-LICENSE](assets/LUCIDE-LICENSE)를 참고하세요.

## 구현 범위와 제약

- 사진·영상 전송, 전화·음성인식, 실제 상대와의 통신, 로그인과 계정 동기화는 구현하지 않았습니다.
- 일반 모드는 전환 완료 안내만 제공하며 전체 기능을 재현하지 않습니다.
- 자동 테스트와 화면 점검은 실제 사용자 사용성 평가를 대신하지 않습니다. 모든 브라우저, 기기와 보조기술 조합을 검사한 것은 아닙니다.
- 실제 고령층 사용자를 대상으로 한 사용성 테스트와 개선 효과 측정은 수행하지 않았습니다.
